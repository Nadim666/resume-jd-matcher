# 简历-JD 匹配度评分工具

把一份简历和若干条岗位 JD 输进去，输出每条 JD 的匹配分、投递建议、以及"这份简历没覆盖到哪些要求"。

全部在本地跑，不联网、不调 API，模型文件 24MB。

## 它解决什么问题

投实习时最耗时间的不是改简历，是判断"这个岗值不值得投"。人肉逐条对 JD 容易漏，
而且很难说清"我到底差在哪一项"。这个工具把这件事拆成两层：

- **技能层**：从 JD 里抽出带技能词的句子，分成「硬要求」和「加分项」（带"优先/加分"字样的算加分），
  逐条对照简历有没有命中。
- **语义层**：把简历和 JD 都切句，用中文语义模型算两两相似度的均值，捕捉技能词表覆盖不到的表达。

两层加权后给总分。**硬要求缺一条就封顶 0.3** —— 技能不齐的岗不该因为"说得像"就被推荐。

## 快速开始

```bash
pip install onnxruntime tokenizers numpy
python get_model.py          # 下载模型到 model/，约 24MB，只需一次
python run_demo.py           # 交互式：选简历、选 JD、看结果
```

命令行直接跑：

```bash
python 简历匹配.py demo_data/我的简历.txt --job demo_data/JD_医疗AI产品.txt
python 简历匹配.py 我的简历.docx --job JD_1.txt JD_2.txt --detail
```

支持 `.txt` / `.md` / `.docx` 输入。`--detail` 会逐条列出没覆盖到的要求，
以及简历里"最接近但不够像"的那句话 —— 改简历时直接照着补。


## 阈值是怎么定的

`demo_自检.py` 用同一份简历跑 5 条不同类型的 JD，看分数分布和阈值敏感性：

```
医疗AI产品  0.600    算法实习  0.360    数据标注  0.356    临床护理  0.339    前端开发  0.184
第一名 / 第二名 = 1.66 倍

阈值 0.40 ~ 0.55 区间内，被推荐的始终只有"医疗AI产品"这一个
```

结论：0.55 的推荐门槛下，排序对阈值不敏感，第一名始终不变。差距大不是运气，
是技能层那一刀（缺硬要求直接封顶）在起作用。

## 两个踩过的坑

**1. 分词器的 lowercase 配置和词表不一致。**
这个 tokenizer 的 normalizer 设的是 `lowercase=False`，但词表里存的是小写，
结果 `Python` 被切成 `[UNK]`，所有英文技能词一个都匹配不上。
代码里手工打开小写后才正常：

```python
self.tok.normalizer.lowercase = True   # 见 简历匹配.py 的 Embedder.__init__
```

表现是"技能层永远是 0"，很难从报错里看出来 —— 没有报错，只是全不命中。

**2. 短英文词的子串误命中。**
`java` 会命中 `javascript`，`sql` 会命中 `mysql`（这个反而是对的，但 `c++` 之类不行）。
对 ≤4 字符的 ASCII 词加了前后字母边界检查：

```python
re.search(r"(?<![a-z])" + re.escape(w) + r"(?![a-z])", low)
```

## 文件结构

```
简历匹配.py      核心：读文件、切句、模型推理、两层打分、命令行输出
run_demo.py      交互式入口（双击 运行demo.bat 走这个）
demo_自检.py     分数分布 + 阈值敏感性实验
get_model.py     下载模型文件
demo_data/       5 条不同类型的 JD + 一份示例简历
model/           模型放这里（不入库，用 get_model.py 下载）
```

## 已知不足

- 技能词表是手写的 14 类，换行业要自己扩 `SKILLS`。
- 语义相似度只看均值，句子少的 JD 分数容易偏高。
- 没有中文分词，切句靠标点，长句里的并列要求会被当成一条。
- 只支持单份简历 vs 多条 JD，没有做简历的"批量改写建议"。

## 用到的模型

`BAAI/bge-small-zh-v1.5` 的 ONNX 量化版，通过 `onnxruntime` 直接推理（不依赖 PyTorch）。
BGE 取的是 `[CLS]` 向量，做归一化后用内积算余弦相似度。
